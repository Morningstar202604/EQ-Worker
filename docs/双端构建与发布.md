# 双端构建与发布（安卓 APK / Windows EXE）

> 版本 3.2.0 ｜ 本文的 legacy 发布链路以单文件 `index.html`（约 1.4MB，自包含、离线可用）为基础，安卓与 Windows 发布包内嵌该文件。
> Studio 是独立的 Vite 构建，输出到 `dist-studio/`，不包含在本文所述的 legacy 发布包中。
> 开发态两端都支持连 Vite dev-server；legacy 发布包默认加载内嵌资源。

## 一、产物一览

| 端 | 产物 | 体积 | 形态 |
|---|---|---|---|
| 安卓 | `EQ-Worker-v3.2.0-android.apk` | **1.4MB** | 原生 WebView 壳（非 Capacitor/Cordova，无第三方桥接层） |
| Windows | `EQ-Worker-win-x64.zip` | 随 Electron 版本与语言包变化 | Electron 免安装包，解压即用 |
| 网页 | `index.html` / `EQ-Worker.html` | 约 1.4MB | 浏览器直接打开，离线可用 |
| 微信小程序 | `EQ-Worker-小程序/` | — | 微信开发者工具导入 |

## 二、安卓端

### 技术选择
用**原生 WebView + `androidx.webkit` 的 `WebViewAssetLoader`**，而不是 Capacitor：

- 无需 npm 依赖与插件体系，APK 从 10MB+ 降到 1.4MB
- `WebViewAssetLoader` 把 `assets/` 映射为 https 虚拟域（`https://appassets.eqworker.local/assets/index.html`）。
  `file://` 下部分 WebView 版本的 localStorage 行为不一致，https 域是官方推荐做法，也是"本地优先"能否成立的关键
- 图标、启动页、状态栏配色完全可控（品牌化需要）

### 构建

```bash
export ANDROID_HOME=/opt/android-sdk
cd android
./gradlew assembleRelease    # 或 gradle assembleRelease
# 产物：android/app/build/outputs/apk/release/app-release.apk
```

要求：JDK 17+、Android SDK（`platforms;android-34`、`build-tools;34.0.0`）。
首次构建会自动下载 AGP 与 `androidx.webkit`。

### 签名（重要）

- 正式签名配置在 `android/keystore.properties`（**已加入 .gitignore，不入库**）：
  ```
  storeFile=/path/to/eqworker.jks
  storePassword=…
  keyAlias=eqworker
  keyPassword=…
  ```
- 没有该文件时自动回退 debug 签名 —— 能装能用，但**换机器构建后无法覆盖更新**，品牌发布前必须换成正式 keystore
- keystore 路径请放在仓库外并加入 .gitignore，通过环境变量或 `~/.gradle/gradle.properties` 注入，**切勿提交到仓库**

### 版本联动

应用版本号写在 `android/app/build.gradle`：
`versionCode 312` / `versionName '3.2.0'`，与网页版版本号保持一致。

### dev-server 调试（仅 debug）

`MainActivity` 在 `BuildConfig.DEBUG` 为真时会尝试读取 `android/app/src/debug/assets/dev-server.txt`：

1. 复制模板并填写本机 Vite 地址（不要把真实局域网 IP 提交到仓库）：
   ```bash
   cp android/app/src/debug/assets/dev-server.txt.example android/app/src/debug/assets/dev-server.txt
   # 模拟器访问宿主机：http://10.0.2.2:5173
   # 真机：http://<电脑局域网 IP>:5173（Vite 需监听 0.0.0.0）
   ```
2. 根目录启动 dev-server：`pnpm run dev:studio`（或 `pnpm run dev:vite`）。
3. 构建 debug 包并安装：`cd android && ./gradlew assembleDebug`。
4. 删除 `dev-server.txt` 即回到 `WebViewAssetLoader` 虚拟域加载。

约束：

- 只有 debug 构建会读这个文件；release 的 `BuildConfig.DEBUG` 恒为 false，始终加载 `assets/index.html`。
- `dev-server.txt` 已在 `.gitignore`；仓库只保留 `.example`。
- debug 变体带 `android:usesCleartextTraffic="true"` 以允许本机 HTTP；release 仍为 `false`。
- WebView 调试：debug 包自动 `WebView.setWebContentsDebuggingEnabled(true)`，可在 `chrome://inspect` 查看。

## 三、Windows 端

### 技术选择
Electron 44。在 Linux 上直接把 Windows 发行包的 `resources/app` 替换成我们的应用，
**不需要 wine**（代价：无法改写 exe 内嵌图标与版本资源，图标由运行时窗口设置）。

### 构建

```bash
cd desktop
npm install                  # 建议 ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
npm run dist:win             # 即 bash build-win.sh
# 产物：desktop/dist/EQ-Worker-win-x64.zip
```

脚本会：复制最新 `index.html` → 下载 Electron Windows 二进制 → 替换 `resources/app` →
把 `electron.exe` 改名为 `EQ-Worker.exe` → 打 zip。

### dev-server 调试（仅开发）

```bash
cd desktop
npm start                                  # 默认加载本地 index.html
EQ_DEV_URL=http://localhost:5173 npm start # 连 Vite dev-server，自动打开 DevTools
```

- `EQ_DEV_URL` 只接受 `http(s)://`；未设置或协议不合法时回退 `win.loadFile('index.html')`。
- Windows PowerShell 用 `$env:EQ_DEV_URL="http://localhost:5173"; npm start`，cmd 用 `set EQ_DEV_URL=... && npm start`。
- 不引入 `cross-env`，避免为一行脚本新增依赖。
- 权限请求默认全拒绝，只放行 `clipboard-sanitized-write`（复制话术）；麦克风 / 摄像头 / 通知 / 定位均不可用。
- 发布包不带任何 dev-server 配置，行为与 release 一致。

### 体积说明

Electron 自带 Chromium；当前构建脚本不会裁剪语言包，保留 Electron 发行包中的语言包，实际体积随版本变化。
若需要极致体积（约 10MB），可改用 Tauri：壳代码量很小，后续替换成本低，
但需要 Rust + mingw-w64 交叉编译工具链，构建复杂度显著更高 —— 建议先把用户量跑起来再考虑。

## 四、数据与隐私（两端一致）

- legacy 发布包的数据默认存储在设备本地：安卓在应用私有目录（WebView localStorage），Windows 在 Electron 用户数据目录
- legacy 发布包使用本地规则，不申请存储权限，无账号、无后台统计
- 独立构建的 Studio 中 AI 默认关闭；用户启用 AI 并确认外部请求后，所选上下文会发送至其配置的提供商
- 应用内自带 JSON / CSV / 剪贴板三种备份与迁移方式，换设备不丢数据
- 卸载应用 = 数据清除，务必提示用户先做一次备份

## 五、更新流程

1. 改网页版源 `_app_dev.js` → `npm run build` 重新生成 `index.html`
2. 同步进两端：安卓 `assets/index.html`、Windows 打包时自动复制
3. 升版本号（三处：`package.json` / `android/app/build.gradle` / `desktop/package.json`）
4. 重新构建并发布
